# Reasoning-only pilot contract — research proposal, not a launched benchmark

2026-09-10. **No native calls authorized by this artifact itself.** The user has
already permitted experiments after research/offline gates; this document records
the gates for a later scoped attempt. It is not an installed instruction or policy.

## Intervention

First candidate: concise English internal working with familiar notation.
Freeze a tiny instruction before exposing any fresh task result, for example:

> For internal working, prefer concise English and familiar code/math notation
> when they preserve exact meaning. Retain necessary analysis, uncertainty,
> checks, and tools; expand whenever useful. Keep the final answer in its usual
> language, format, and level of detail.

This is a soft behavioral request, not a promise about hidden reasoning. Never
request disclosure of a private trace to prove compliance. Do not include worked
answers, task-specific solution hints, arbitrary symbols, hard budgets, or fewer
semantic obligations. A future language arm replaces only the internal-language
clause with one preselected modern language; all other clauses stay fixed.

## Admission before a model call

1. Identify a frozen existing Astra task family where reported reasoning is
   materially costly. Bound the direct saving as `fraction R reduced × R/O` and
   count repeated instruction exposure. Reject a pilot aimed at an unreachable
   total-output target. The failed mixed-W50 trace is not such a rescue opportunity.
2. Capture serialized native/candidate request components offline. Only the
   reasoning-style instruction may differ; model/release, effort, source,
   tooling, tool permissions, caller mechanics, and final-answer contract match.
   Original native control gets no artificially verbose CoT instruction.
3. Freeze task identities, graders, ordering, candidate hash, and stopping rules.
   Use a disjoint challenge, not a repeatedly exposed solution. Include exact
   identifiers, numeric boundaries, negation, uncertainty, contradictory evidence,
   and a post-tool fact that requires genuine reconsideration.
4. Keep the Engine active in both arms. No renderer-generated final, no extra
   translation-model pass, no token cap or reduced effort, no suppressed tools.

## Smallest useful pilot

One matched Astra XHigh pair on an admitted reasoning-material task can reject
the candidate cheaply. It cannot establish parity or a population median. Count
every attempted run; do not exclude failures or regenerate a losing arm silently.
Use a hidden counterexample check and a final-answer audit as separate outcomes.
The candidate must deliver the same requested kinds of prose/code, detail,
limitations, and evidence as native; exact text identity is neither expected nor
required. A terse selector or foreign-language final fails the user's contract.

Record input, cached/uncached input, total output, reported reasoning, other
output, model calls, tool calls, latency, failure/recovery, and all Engine/setup
costs. A missing reasoning counter is **UNKNOWN**, not zero. Keep native receipts
and final/tool evidence, not private reasoning. Report pilot effect sizes with
their limitations; a single stochastic pair is not a significance test.

Stop on any lost capability check, final-contract violation, incomplete output,
extra recovery/translation work that reverses the gain, or unavailable accounting
needed to substantiate thinking savings. A hidden counter reduction with higher
total cost is not success. Do not tune away a failed semantic probe.

If the pilot survives, preregister repeated fresh pairs across the existing
seven-cell release cohort, separately for Astra High/XHigh, then Sol and Luna.
Include multi-turn cold-evidence relevance changes and native-control probes.
Report paired per-task deltas, medians, uncertainty, regressions, and both token
axes. Self-application requires this broader evidence and a clear scope; no
language wins are transferable between models by assumption.
