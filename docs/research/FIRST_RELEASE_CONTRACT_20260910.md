# First release: median economics and capability/workflow parity

Latest user correction, 2026-09-10, supersedes per-family release thresholds and
compact-selector final answers. Capability first;80/80 remains aspirational.

## Hard gates

- Astra High and Extra High are separate cells. Each needs median input and output
  savings >=65% across the predefined cohort. Sol High needs both medians >=75%.
  Luna retains its previously accepted75/75 target and separate scoped results.
- Final answers must be model-written, ordinary prose/code with native-equivalent
  completeness. Internal structured tools are allowed. Final selector/edit JSON
  and caller-rendered replacement answers are inadmissible under this contract.
- Preserve ordinary tools, semantic review, questions, evidence and recovery.
  Engine remains active; ordinary semantic execution may remain inside its workflow.
- No missing requirement/artifact, known semantic defect, lost future-relevant
  evidence, unauthorized action or suppressed recovery is accepted for savings.
- Freeze profile/kernel/skill/tool schemas, tasks and graders before qualification.
  A frozen model label/effort does not imply immutable hosted model weights.

## Cohort before new outcomes

Use the established task inventory: interval coding, dependency coding, transaction
coding, existing-code maintenance, exact selection/retrieval, cold recovery, and
W50 delayed-relevance/continuation. Seven equal-weight task cells per model/effort
for the primary median. Also show family medians and ratio-of-totals. No silent
reweighting, failure exclusion or extra easy cases to improve the median. These
are exposed development tasks; independently frozen holdouts must be separate.

Keep historical90/90 wins and their confidence labels. Do not splice incompatible
output-contract results into the new cohort. Missing/unqualified cells remain
unknown. One interface pilot precedes the full cohort to avoid unnecessary calls.

## Capability/workflow qualification

Check both native and Helix artifacts with the existing behavioral oracles. Add
stale/conflicting authority, changed requirements, semantic error despite mechanical
PASS, unsupported operations, delayed relevance, exact recovery, duplicate delivery,
restart and interrupted publication. Unknown execution cannot become a success
claim. Deterministic transitions cannot authorize semantic decisions.

Inspect final native agent-message items: model authorship after relevant execution
results, complete requested content, truthful claims, ordinary answer structure.
Exact prose equality is unnecessary; content/structure completeness is required.
Freeze only after all cohort cells are accounted for and no measured capability or
workflow regression remains. Finite parity remains scoped, not universal proof.

## Accounting and deployment

Charge every native attempt, repair, final continuation, preparation, retrieval,
storage, recovery and coordination. Separate cached/uncached input, output/reasoning,
calls, latency and Engine costs. Current API tariff estimates are not actual Codex
quota or total ROI. Keep coordinator research costs separately visible. Live prices
refresh/expire; static reports keep dated snapshots.

Fix the publication-lock inventory prospectively; preserve the old stopped run.
Validate Extra High in native requests/replies before inference. No global settings
changes or unverified production hooks. Normal Codex-app integration is a distinct
release gate; a research caller is not the installed app product.
