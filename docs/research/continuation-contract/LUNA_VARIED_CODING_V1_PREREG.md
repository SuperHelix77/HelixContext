# Frozen Luna profile: prospective varied coding qualification

Hypothesis: the frozen V7 base and V3 caller-completion composition can remove
repeated acquisition/mechanics on other single-module coding tasks without losing
finite contractual behavior. No profile tuning, effort reduction, tool restriction
or output cap. The prior allocation result remains a separate known-task candidate.

Three new researcher-authored contracts: half-open interval union, lexicographic
dependency scheduling, and atomic/idempotent account updates. Each has buggy source,
public tests and an independently frozen finite grader. Correct offline reference
implementations test the graders; neither arm receives those implementations or
private grader source. This is prospective development evidence, not a population
holdout or a claim that the researcher was blind.

Both arms receive actual task/directory-bound memory preflight and the same local
instruction recognizing its completion. The control uses the default client base
and ordinary tools. The candidate uses the exact frozen 6,188-byte base, attached
skill, exact supplied task files, source-only result and caller staging/checking.
The same user contract, public tests, High effort, workspace-write sandbox and
ordinary tools remain available. This removes the prior control-memory permission
failure confound. It is a composite product test, not a kernel-only ablation or raw
desktop deployment comparison. Each arm's preflight/setup costs remain recorded.

Freeze source/checks/runner before six native streams. Randomize order inside each
pair. Start each arm in a fresh directory/thread; preserve all native input, output,
reasoning counters, raw tool calls and exact generated files. Candidate check
failure returns exact diagnostics for at most one further semantic turn. This is
an experiment budget, not a release rule suppressing needed reasoning. No blind
retry. Record semantic-attention/parse failures. Complete the prespecified other
independent cases after a behavior miss; stop globally for integrity/infrastructure
failure. Numerical failure never triggers another candidate on the same fixture.

Audit native receipts, exact final source and protected files. Report all pairs,
per-task input/output/uncached savings, medians and complete attempted native cost.
Keep N=3 descriptive; do not pool with retained/adaptive allocation runs or zero-call
retrieval replays. Capability gates take priority over any 75/75 or 80/80 savings.
Public finite checks do not certify general intelligence/workflow parity.

Still outside this experiment: arbitrary multi-file projects, unseen long workflows,
normal Codex UI integration, hostile concurrent-writer publication isolation and
complete physical/research cost accounting. Engine remains active; unsupported
semantics stay with the model. No global model or Codex configuration change.
