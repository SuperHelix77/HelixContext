## What changed

V2 already returned source only and let Engine check/publish it, but Luna repeated an initial memory recall that failed opening global `server.log` inside the sandbox. V3 performed that recall in caller preflight, retained its exact evidence, bound the receipt to the task/directory, and added a local AGENTS rule recognizing the completed obligation. Global instructions and production configuration were unchanged.

The preflight succeeded. Eight memory hits from other scopes were excluded under this fixture's rule against other runs/evaluators; raw results remained cold. No benchmark answer was injected. This task-local scoping is a research constraint, not a general replacement for cross-project memory.

The local rule permits another targeted recall for new semantic needs, and falls back to ordinary memory handling for absent or stale receipts. Timeout/service failure is recorded as unavailable, never success. Four offline tests rejected changed task/scope, altered metadata/raw evidence and invalid replies, and checked optional failure handling.

INFERRED: Recognizing caller-completed memory preflight plausibly removed the duplicate call. Both the explicit instruction and bound receipt changed together, and model variation remains possible; this run does not isolate their individual causal effects. It does establish that the new path completed the task without the previous duplicate call.
