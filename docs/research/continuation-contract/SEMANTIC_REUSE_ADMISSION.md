## Narrowest admissible reuse boundary

First falsifier should attempt exact-bound decision reuse only. Do not infer
semantic equivalence between different requests or ignore apparently irrelevant
new evidence. An entry must bind the exact request, complete evidence snapshot,
authority/policy versions, model/reasoning/release, skill and instructions, renderer,
checker, and explicit obligations. It contains the auditable decision and exact
sources, never private reasoning. Missing binding means no reuse.

Reuse is inadmissible when any of those bindings changes, when time or external
state is decision-relevant but unbound, or when the original decision had unresolved
obligations. No mechanically passing receipt may upgrade semantic sufficiency.
Explicit re-review requests always invoke semantic review. A valid prior result
is required; V2 and the original V3 schema failure are ineligible. A recovered
result requires the adapter version and recovery check to be bound separately.

This conservative boundary may have very few hits. That is a measurable negative
result, not permission to discard dependencies. More selective invalidation would
need its own evidence before widening admission.

## Required cheap falsifiers before native launch

| Case | Required disposition |
|---|---|
| Identical request, all bindings and accepted decision unchanged | Eligible for exact reuse; still account lookup/validation/publication |
| Requested approver count changes | Native semantic decision |
| Requested group changes | Native semantic decision |
| Late evidence changes meaning of an old otherwise irrelevant fact | Native decision with exact old and new evidence |
| Policy/amendment changes under reused path | Invalidate despite stable path |
| New authority or revoked authority | Invalidate |
| Changed checker, renderer, skill, model or reasoning release | Invalidate |
| Missing/corrupt evidence or unsupported amendment scope | Recover exact evidence or native fallback; no stale result |
| Correct hashes but wrong reason code | Independent reason check rejects; do not reuse |
| User explicitly requests reconsideration | Native review even if all bytes identical |
| Interrupted publication/restart | No successful receipt until complete; preserve failed attempt |
| New dependency omitted from a compact view | Complete-world binding changes; invalidate |

Use task variants whose expected decisions actually differ: at least one boundary
must switch authorization, one must change source authority, and one must make an
early detail newly decisive. Repeated ACKs cannot stand in for these cases.
Positive authorization must not be certified by the current negative-reason checker;
it currently returns unresolved because the full obligation set is not closed.

## Next native experiment admission

No new native call is authorized by this document alone. First identify eligible
repeated semantic work in an independent workload without looking at its candidate
savings. Freeze full task requirements, ground truth and dependency manifest.
Then run fresh persistent native and Helix arms with the same model, reasoning,
tools, authority and checkpoints. Count every fallback and recovery. Do not reuse
older expensive controls. Require correct final artifacts, reason entailment,
required intermediate actions and exact late evidence recovery.

Stop on any stale-result reuse, missed reconsideration, unsupported obligation
silently accepted, or hidden recovery charge. If safe hit rate is below the
per-axis break-even frontier, reject the architecture for that model/task cell
before a broad sweep. Keep native bypass; do not weaken correctness to create hits.
