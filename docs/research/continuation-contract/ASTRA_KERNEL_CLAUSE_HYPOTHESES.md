# Astra V1 clause audit: association, not causal attribution

OBSERVED: the valid kernel run added iteration-entry exceptions and legacy-sequence
failure/recovery probes; default accepted with source reasoning and supplied test
evidence. The kernel's own commentary said it would test semantic gaps. This is
observable behavior, not evidence that one instruction caused it.

| Wording candidate | Plausible connection | Counterevidence / limit |
|---|---|---|
| “Investigate assumptions, specification coverage, boundary cases and unchecked obligations” | Can read as an affirmative request for extra investigation | Ordinary task also requires semantic review; no clause ablation exists |
| “Retain novel-probe and rejection authority even when every provided checker passes” | May frame successful checks as a cue to probe | Grants authority rather than requiring use; cannot infer how model weighted it |
| “Never suppress novel semantic probes to save tokens” | Might discourage ending review when existing evidence suffices | Protects real capability; removing it could suppress necessary checks |
| Whole shortened base | Changes relative salience of all retained instructions | Cannot isolate this effect from one paired stochastic outcome |

HYPOTHESIS: V1 changed both mechanical responsibility and investigation intensity.
It is not proved that skepticism increased as a general model property. The valid
probes can have real assurance value even though no defect was found. Do not call
them unnecessary merely because the expected outcome was ACCEPT.

Candidate V2 direction, not activated: maintain ordinary task-dependent standards
for adequacy; reuse bound mechanical facts without creating an extra investigation
obligation solely because Helix is present. Preserve retrieval, independent-review
requests, conflicting-evidence escalation and novel probes when needed.

“Use ordinary review depth” is itself counterfactual and not directly observable
within one arm. Qualify through matched obligation coverage, actual defects caught
and recovery behavior, not a fixed probe count or turn cap. No exact trigger clause
can be determined from these traces alone. No new Astra model run authorized by
this audit; current work priority remains Luna.
