# Luna coding: one frozen-component composition

Hypothesis: the previously tested compact V7 delegation base can complement the
newer V3 caller-owned coding path. V7's earlier general coding trial still incurred
setup/mechanics; V3 removed them but used the default base. This composition has
not been measured. It is not a new kernel wording or an output cap.

The candidate uses the exact 6,188-byte V7 base (SHA256
`f07e19dbe57d410b23524332acf30c0f19650ab631f9e654897cbf440c61c4c0`).
Prompt, skill and local caller-memory instruction bytes must match the prior V3
candidate. Default High effort, tools, sandbox, source-only interface, protected
files, public tests, independent oracle and failure re-entry remain in place.
Only the client base is replaced; server-side additions remain unknown.

One new candidate stream. No blind retry. The existing V3 allowance of a second
semantic turn applies only to actual checker failure. The retained fresh native
control and retained default-base V3 candidate are two separate reference rows;
neither is a fresh simultaneous pair. All output includes reported reasoning.

Offline gate: exact component hashes, unchanged prompt/skill/local instruction,
scoped actual memory preflight and thread-local config placement. Audit native
metadata for the exact base text and raw receipts for every tool call. Require
the four public tests, 4,433-case oracle, protected inputs and exact publication.
Any scope/behavior/binding/receipt failure prevents qualification. Do not change
the task, lower effort or retry an unfavorable sample.

Outcome: report both comparisons, separate uncached input, segments, commands,
memory/capture/check costs and limitations. A numerical 75/75 or 80/80 observation
remains an adaptive candidate until fresh qualification. A regression leaves the
existing default-base policy intact. No global Codex configuration changes.
