## Why the original result changed

**OBSERVED — V1:** the initial six-stream suite measured 89.51% median input and
80.35% output savings. Task directories inherited an ancestor Git repository.
Two controls returned about 357 KB and 360 KB of broad Git metadata/status.
Runtime truncation means those terminal bytes cannot be equated with native
model-visible tokens. One control also inspected a workflow skill; another
created and corrected a mistaken additional test expectation. V1 is retained as
scope-confounded development, not clean qualification.

**OBSERVED — V2:** isolated tracked Git roots fixed the scope confound. The first
control then hit the global-config hash guard after completing inference. Exact
initial configuration contents were not retained, so the cause remains
**UNKNOWN**. Raw receipts were recovered without inference and its 615 finite
checks passed. The other five arms were not run; this is not a complete pair.

**OBSERVED — V3:** a stricter effective-config wrapper retains private snapshots,
binds all non-overridden settings and captures raw evidence even after failure.
The first candidate completed one semantic turn but hit the guard because the
native client added exactly its task directory's `trust_level="trusted"` marker.
No other effective setting changed, and no project `.codex` configuration existed.
The original wrapper failure and original stopped result remain unchanged.

The candidate's already-generated exact bytes were staged, checked and published
after that narrow audit, with no new model call. Native project registration for
all six roots was then moved before inference/config freeze: **0.8676 seconds,
zero `turn/start` calls**. The five unrun arms completed under the unchanged
effective-config guard. This explicitly amended continuation is not described as
