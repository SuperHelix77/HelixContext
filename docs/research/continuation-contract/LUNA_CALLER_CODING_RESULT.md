## Execution and original failure

Luna did not repeat skill activation or runtime discovery in this trace. It reread
the supplied task files, then built a temporary test harness instead of leaving
all test execution to the caller. One cleanup command containing `rm -rf` was
rejected by the shell safety layer; Luna subsequently used a safer command and
reported four passing public tests. Those attempts remain charged in the native
receipt. Ordinary tool-recovery within the turn is not erased as overhead.

The final JSON contained complete source and substantive assessment. Its
`unresolved` array contained exactly two already-assigned caller obligations:
run the independent allocation oracle on that source, then atomically publish
only after successful checks. The driver required an empty array before even
executing those checks and stopped. This is a workflow-contract defect in the
experiment: pending deterministic work and unresolved semantic judgment were
represented in the same field.

## Adjudication

Registration handoff worked on this observation; overall caller-delegation behavior
did not meet the desired economics. Do not attribute all regression to setup or
silently remove semantic self-tests. Reported reasoning alone exceeded the whole
control's output, so trimming final JSON could not make this observed trajectory
an 80%-output win. That is a conditional arithmetic statement, not a proved model
reasoning floor or access to hidden cognition.

Any revised execution contract must distinguish semantic obligations from declared
pending caller steps. Caller steps can progress to exact receipts; unresolved
semantics require the model. However, fixing that contract alone cannot remove
the already-spent 5,361 output tokens and does not justify another native rerun
without an independently supported behavioral intervention.

The selection trace also supplies a useful conditional admission bound: its native
control uses 57,216 input tokens, giving an 80% budget of 11,443.2. The prior Helix
selection first segment alone used 15,487. Keeping that first-segment setup unchanged
rules out 80% input regardless of later reductions. This is not a universal
platform lower bound; different input assembly remains a separate hypothesis.
