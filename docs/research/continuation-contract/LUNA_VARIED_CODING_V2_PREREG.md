# V2: repair the repository boundary, preserve the candidate

V1's six streams passed their finite graders. Median input/output savings were
89.51% / 80.35%; all three pairs cleared 75/75. Those results are retained.
However, two native controls ran Git status against the ancestor research repo,
returning about 357–360 KB of unrelated filenames. The fixtures were untracked,
so normal diff inspection did not work. One control also discovered/attempted
registration of a different skill; another corrected its own erroneous probe.
These are observed trajectory costs, not evidence of a universal Helix advantage.
Raw terminal bytes are not native-token counts or an exact causal attribution.

V2 freezes the same contracts, buggy source, public/private graders, task prompts,
V7 base, High effort and full ordinary tools. Both arms still have matched actual
memory preflight. Only preparation changes: each arm starts as an isolated Git repo
with source/tests/settings and instructions tracked, plus ignored runtime artifacts.
Offline tests must establish correct repository root, empty initial status, a real
source diff and absence of sibling metadata. This isolates ordinary coding behavior
from the inherited-repository artifact. No profile improvement or result retry is
being hidden: these are six new native streams, with V1 retained separately.

One fresh pair per known task, randomized arm order. Same two-semantic-turn candidate
budget and failure/recovery rules as V1. Preserve all attempts. Stop on integrity or
infrastructure failure. Numerical misses receive diagnosis, not another same-policy
retry. Report medians and per-task thresholds; do not merge V1/V2 into N=6 independent
tasks. This is known-task replication after a harness correction, not unseen holdout.
