# Live-thread research session: continuation accounting prerequisite

**OBSERVED engineering tests; no new inference, native recovery unqualified.**

The prior one-turn runner closes its RPC connection after returning. A separate
`engine/output/research_session.py` now retains that connection and thread across
explicit caller-driven turns. The existing runner, frozen skill and production
routing are unchanged. This wrapper contains no semantic-closure decision rule.

## Protocol evidence

Official app-server documentation specifies turn/start on a target thread and
standalone toolOutput with empty user input. The installed binary's experimental
JSON schema independently includes TurnStartParams.toolOutput and thread/turn IDs
on usage notifications. Local schema generated without inference at
`/tmp/helix-continuation-schema-20260909`.

Source checked 2026-09-09:
https://learn.chatgpt.com/docs/app-server

A continuation can therefore carry Engine results as tool output on the existing
thread rather than pretending they are a new user instruction or starting an
unrelated fresh conversation. This is protocol support, not demonstrated model
recovery, cost saving, or a guarantee about the platform's rendered context.

## Implemented safeguards

- Initialize/start one thread per session, with fixed model, High effort, ordinary
  workspace tools and the existing requested 512-token skill-catalog cap.
- Optional native skill attachment and caller registration occur before the first
  inference. No repeated skill lesson is generated by the wrapper.
- Explicit text or named tool output per turn, never both. Recovery is requested
  by the caller, not an automatic retry or heuristic router.
- Store turn input and STARTED status before dispatch. Retain raw native events,
  normalized events, per-turn answers, cumulative usage and per-turn deltas.
- Use final cumulative usage once for the session. Turn cost is current cumulative
  minus previous cumulative, not a sum of cumulative updates.
- Require current thread/turn attribution and valid monotonic counters. Missing,
  stale or invalid usage fails accounting rather than implying zero cost.
- Failed turns retain observed partial cumulative cost. After failure, forbid
  another turn in that session. Unknown effects need reconciliation.
- Select answers only from the current thread/turn, never reuse an old final answer.

## Unqualified boundaries / next gate

No real second native turn has run through this wrapper yet. Schema support alone
does not certify actual event ordering or skill persistence across compaction.
The wrapper expects attributable usage by turn completion and fails otherwise.
A process loss does not resume an ephemeral thread; exact recorded evidence is
retained, but cross-process recovery requires a separately qualified design.
Actual semantic detection, successful correction of changed obligations, end-to-end
accounting, and workflow parity remain open. The wrapper does not reduce tool
access, override reasoning effort, suppress semantic review, edit platform history,
or infer completeness of assumptions from mechanical PASS.

Next freeze one real exception-continuation task with explicit source/contract
version changes and independently checked recovery. Use its actual cumulative
receipts to qualify the transport before interpreting any timing comparison. Do
not call the offline tests recovery success or claim 80/80 from this change.
