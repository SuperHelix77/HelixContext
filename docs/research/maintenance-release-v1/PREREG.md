# First-release maintenance cells: Astra Extra High and Sol High

User-set economic gate: Astra >=65% separate input/output savings; Sol >=75%.
Capability/workflow checks still take precedence. These thresholds do not convert
unknown general capability, unsafe production integration or failed task families
into a qualified release. A first release must name its measured workload scope.

One fresh randomized pair per cell, Astra Extra High first and Sol High second.
Both arms in a cell use the exact requested model/effort. Fresh control for each;
no High control reused for Extra High and no provider/model identity substitution.
Known maintenance task, source and public tests are exactly those in the preceding
Astra High experiment. This is transfer on exposed development material, not a
fresh task holdout or independent replication. Model-visible cross-run access is
out of scope; task-bound memory excludes other experiment records.

Control default client base; candidate same preexisting model-specific delegation
kernel, native Helix skill attachment, complete relevant files and exact old/new
JSON. Engine does copying, tests and publication. Semantic authority and ordinary
tool access remain with the model. No task solution is supplied by the caller.
This remains a composite product test, not one-mechanism attribution.

The only caller repair since the preceding maintenance pair: pre-create and track
the exact empty publication lock in both workspaces before their initial Git commit.
It is bound by the frozen manifest, so any content change is still an integrity
failure. An offline test exercises real publication and verifies the scope check,
then confirms foreign lock content is rejected. Original failed protocol untouched.

The versioned session explicitly sends/validates effort on thread/start and every
turn/start, records it in status, and checks the native effective reply. A no-turn
native preflight must confirm Extra High before inference. No global model or
effort setting changes. Registration for all four roots happens before the final
shared effective-configuration snapshot is frozen. Only already-explicit model/
effort GUI default changes are allowed afterward; other configuration drift stops.

At most two native user turns per arm: one initial turn, one semantic repair only
after a real failed check/edit. No blind retry or prompt adjustment. Integrity,
configuration or infrastructure failure stops globally; exact retained recovery
may be audited separately with the original failure preserved. All attempt tokens,
cached/uncached counters, reasoning counters, tools, checks, setup, storage,
publication, latency limits and research overhead are reported.

Freeze concrete runners, prompts, source/checkers, configuration and per-cell
manifests publicly before either pair. No native call before offline gates.
Audit task artifacts, exact candidate assembly, native identities and counters,
skill/base/effort attachment, config and protected files before qualification.

If both cells clear their economic/finite gates, prepare a scoped first-release
candidate with existing qualified Luna/W50 results and explicit failed/unknown
families. Engine remains active for ordinary semantic workflows; unqualified
cost reductions are never advertised. Full normal Codex-app pre-inference delivery
is still a separate integration gate. If a cell fails, diagnose the retained trace
and stop that policy; do not tune and rebuy this known task until it passes.
