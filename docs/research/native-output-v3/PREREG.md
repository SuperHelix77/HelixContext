## Evidence and boundary

OBSERVED: V2 Sol used four segments despite a correct exact-diff receipt. It read
current source/scope, emitted a full-function old/new edit, then checked scope,
diff, whitespace and SHA before its final answer. Saving was44.79% input,9.81%
output,8.46% uncached. That policy is not admitted.

CONDITIONAL: removing its entire first and third segments would retain51,175 input
and1,033 output tokens: only71.92%/56.69% savings against that control. This is
optimistic trace arithmetic, not an achievable counterfactual or universal floor.
Scope wording alone therefore cannot hit75/75 under that unchanged remainder.

## Three independently versioned changes

1. `indexed_lines_v1`: model selects original LF line ranges and exact insertions.
   Caller copies unchanged bytes. No old-text retranscription, fuzzy matching,
   semantic repair or solved answer supplied to the model.
2. `complete_target_indexed_v1`: caller shows the COMPLETE edit-target file with
   line addresses; other exact task files remain cold at their ordinary paths,
   with SHA/byte inventory. Selection is the task's explicitly named editable
   file, not a learned semantic completeness judgment. Retrieving tests or helper
   source remains permitted and fully charged.
3. `bound_diff_and_scope_v1`: actual initial/post Git HEAD/status, whitespace-check
   exit and source identity, with full raw evidence. The existing authority callback
   rechecks declared protected state. No exclusive custody, future-state guarantee,
   semantic adequacy, test sufficiency or dependency completeness is certified.

Keep the V1 lifecycle, existing Sol kernel, skill and native transport unchanged.
The native caller retains exact edit requests, binding, staging/check failures,
publication, duplicate/restart recovery, returned evidence and final model messages.
Both arms are told the available pytest entrypoint is `python3 -m pytest`; this
prospective environment clarification removes a known avoidable control detour.
Neither arm receives old solutions, model traces, replay-derived edits or oracle code.

## Offline gates before inference

Exact LF/CRLF/Unicode/EOF and overlapping/range/stale rejection; independent generated
edit oracle; unchanged cold inventory; bad checks preserve original; duplicate and
restart are idempotent; lost scope ACK reconciles without re-execution; altered
protected state or false scope cannot publish a success receipt. Correctly hashed
wrong semantics remains semantically wrong. A whitespace failure stays visible.
Replay the already-observed V2 artifact OFFLINE ONLY and independently apply its
diff. Record request/source/receipt bytes, all available Engine I/O and elapsed cost.

## Native execution and adjudication

One fresh Sol High off/on pair, randomized order, isolated matching task directories;
two task-level semantic turns maximum per arm for actual artifact failure recovery,
ordinary internal model continuations unrestricted. No blind retries. Native counters,
config and explicit effort/source/tool identity must audit; every failure is charged.
The comparison is the whole candidate policy versus native, not isolated attribution
to any one switch. One stochastic exposed pair cannot establish general parity.

Mechanistic gate: can the candidate apply its own semantic change without copying
the full old function and without a separate equivalent source/scope inspection?
Required semantic probes are not deletable overhead. Native final authorship,
completeness, truthful check claims and normal link/output conventions must pass.

Stop inference on drift, uncertain publication, invalid capture or authorization.
Do not restart the same run to repair instrumentation. Reject as an economic policy
if it recreates the repeated model work or introduces a capability/workflow defect.
If it removes that work safely, keep the actual result even when one maintenance
cell misses75/75; proceed only to the predefined cohort/independent falsifiers,
