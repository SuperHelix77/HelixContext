The stronger Q4 control already computes directly over an original source file. A verifies integer allocation behavior on 116 evaluator cases, existing test execution and unrelated-file preservation. W50 checks amendment/authority handling and exact historical recovery. L40 selects an early ordinary Unicode/whitespace-bearing label only at turn41 and requires exact reconstruction and provenance. These are four logical episodes per model, not hundreds of independent capability samples.

A/W reuse original same-model High controls and exposed development fixtures. Q4 and L40 use fresh controls; the candidate was frozen first. Every turn uses a fresh native invocation with caller-reconstructed context. The skill body is loaded only for substantive decisions on long-horizon on-runs; all passive turns still call the same High model. Caller-file integrity and actual cold retrieval are graded. This does not test native persistent-session compaction or arbitrary dependent-action workflows, and causal prompts are not OS-level isolation from evaluator files.

## What the iterations taught us

The first policy recovered evidence but induced redundant bookkeeping, tool calls and generation. Those receipts remain published, including Luna's large cost regressions. Explicit caller ownership and progressive loading address that observed failure. Compact data views offered less value once normal controls used direct-file computation. The ambiguous earlier output-field/source-ID mapping is recorded separately; Q4 fixes it prospectively. No original failed grade was rewritten.

The cold archive used here retains every released user event and final assistant answer. Full native tool traces remain locally retained for auditing, but these fixtures do not establish a general retrievable archive for arbitrary tool-state dependencies. A response index is not a validated long-term decision ledger.

## Hidden prices

`results/frontier-native-usage.json` includes all measured development candidates and native calls, not only the selected policy. `results/cost-audit.json` reports the known project token cost as a lower bound. Parent/reviewer accounting and remote compute are incomplete; no whole-project break-even or billing claim is justified. Cache input and reasoning output are subsets, not extra tokens. Native receipts include skill context, generation, tool arguments and recoveries. CPU, archive writes and descriptive concurrent-run latency appear in `results/frontier-v3.json`; missing values remain unknown. File lengths are not allocated disk blocks.

The installed prose skill cannot remove context already submitted to a model. The tested context selection and progressive loading depend on an external caller. The next research direction is an identity policy for already-efficient tasks and a broader active-workflow evaluation, not shorter reasoning or fewer required checks. General no-loss and a global maximum remain open.
