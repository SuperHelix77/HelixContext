# Fresh memory diagnostic: control completed, pair stopped

A new Luna High diagnostic was launched with a frozen source/prompt/candidate
manifest, identical raw history available to both arms and a two-call maximum.
The control received replayed history; the unlaunched candidate would receive
the Helix skill and exact memory records selected by the literal task term.
Both allowed ordinary efficient tools, required artifact verification and
preserved High reasoning. This was one task over 50 stored events, not 50 native
turns, and was never a universal parity gate.

The control correctly wrote and verified the latest code/revision and boolean
while preserving the unchanged original region. Raw history remained unchanged.

| Native control measurement | Value |
|---|---:|
| Input tokens | 194,759 |
| Reported cached input | 167,424 |
| Input minus reported cached | 27,335 |
| Output tokens | 1,659 |
| Reported reasoning output | 674 |
| Elapsed | 49.292 s |

The predeclared stop rule prohibited the candidate launch if the control exceeded
60,000 input or 4,000 output tokens. Input exceeded that threshold; the candidate
was not launched. This is a budget-stopped control, not a failed answer or a
paired saving. Input/output savings are null, not zero or estimated from payloads.

The post-call threshold did not cap spend inside the multi-tool native turn. The
trace includes source inspection, file creation and verification; repeated model
context contributes to total usage. Cached tokens are reported separately without
inventing a dollar conversion. Future budget design must account for full agentic
turns rather than assuming that initial prompt length bounds total native input.

`MEMORY_NATIVE_CONTROL_STOP.json` records raw-trace/status hashes and local
artifact paths. No further native calls are scheduled by this diagnostic. Do not
drop ordinary verification or constrain the control to one command merely to fit
the budget, and do not silently increase this frozen experiment's threshold.
